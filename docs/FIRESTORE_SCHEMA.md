# Firestore 데이터 구조 v3

초기화 적용 시 활성 정책 문서: `leave_policies/2026-07-17-v4`

## 컬렉션

| 컬렉션 | 용도 |
|---|---|
| `employees` | 입사일, 소속 팀, 직책(`position`), 권한(`permission`), Slack 사용자 ID 및 직접 승인자 |
| `teams` | 플랫폼팀, AI Research팀, 전략기획팀, 경영지원팀과 각 팀장 |
| `leave_policies` | 버전별 연차·포상휴가·승인·취소 정책 |
| `leave_ledger` | 자동 발생, 기존 사용량, 승인 차감, 취소 복원, 관리자 조정 원장 |
| `reward_grants` | 지급 건별 포상휴가와 만료일 및 잔액 |
| `reward_allocations` | 포상휴가 신청이 어느 지급 건을 예약·사용했는지 기록 |
| `leave_requests` | 연차 신청, 담당 승인자 스냅샷, 승인·거절·취소 상태 |
| `notification_logs` | Slack 메시지와 재시도 결과 |
| `audit_logs` | 직원·팀·정책·승인 변경 이력 |
| `schema_versions` | 애플리케이션이 기대하는 필드 구조 |
| `system_settings` | 현재 사용하는 정책 및 스키마 버전 |

## 중요한 원칙

- 잔여 연차를 직원 문서에 직접 저장하지 않고 `leave_ledger` 합계로 계산한다.
- 직책은 대표·팀장·직원, 권한은 관리자·일반으로 서로 독립적으로 관리한다.
- 월차 발생 기간에는 미사용 월차를 누적한다. 첫 비례 연차와 이후 매년 1월 1일 연차를 부여하기 직전에는 이전 미사용 정기 연차를 `EXPIRATION` 원장으로 전부 소멸시킨다.
- 승인 대기 신청은 잔액을 예약하며 거절·취소 시 복원한다.
- 승인된 신청은 첫 실제 사용일 전에 전체 신청을 취소하면 잔여 휴가를 복원한다.
- 첫 실제 사용일 당일 이후의 승인 신청은 관리자만 기록을 취소할 수 있고 사용량은 자동 복원하지 않는다.
- 포상휴가는 지급 건별로 저장하고 실제 사용일에 유효한 건만 만료일 순으로 배정한다.
- 관리자는 모든 활성 직원에게, 팀장은 자신이 담당하는 팀의 직원에게 포상 연차를 지급할 수 있다.
- 신청 당시 담당 승인자와 Slack 수신자를 저장하여 이후 팀 변경이 과거 신청에 영향을 주지 않게 한다.
- 정책은 기존 문서를 수정하지 않고 새 버전을 만든 뒤 `system_settings/current` 포인터를 변경한다.
